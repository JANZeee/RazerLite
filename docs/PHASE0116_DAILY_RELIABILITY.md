# 0.11.6：日常可靠性与安装验收

日期：2026-11-10（Asia/Singapore）。版本 0.11.6 / build 24，诊断 schema 10。本轮修复已有功能，未新增设备命令、依赖、轮询或通知权限请求。

## 修复

### 电量读数不会回退到旧来源

独立电量查询期间，同一 USB 设备的非控制 HID 接口可能加入或移除。控制会话仍然有效，但响应的完整接口列表已不匹配。原来直接丢弃响应后，界面可能重新展示上次组合读取中的电量。

现在独立读取会先清除各来源的当前电量，保留 DPI、充电状态及带时间的成功历史。当前会话内不匹配的响应记录为明确失败，不使用其百分比或时间；已经断连、暂停或停止的旧请求继续直接丢弃。接口再变化也不会恢复旧电量，新的有效 0% 仍可正常显示。

### 低电量提醒可以从长时间等待中恢复

通知权限检查或投递超过读数有效期后，会释放该次提醒的等待状态；之后的新鲜低电量读数可以再次触发。迟到操作只取消自己的待投递通知，不会清除其他设备或新一轮提醒。关闭提醒及退出应用仍清除全部待投递请求；不宣称能撤回系统已经显示的通知。默认不开启提醒，只有显式开启才申请权限。

### 安装更新失败保留可恢复的旧版本

安装器校验源包、暂存包与最终包的签名、应用标识和 Release 配置；并发安装被拒绝。移动、最终签名校验或可捕获中断失败时，尝试恢复旧包。恢复失败则保留备份并输出恢复位置；首次失败清理本事务的未验证新包。清理依据预先记录的移动意图和目录身份，不依赖移动后才能设置的标记，也不删除被其他程序替换的目标。

安装不注册登录项，不修改本地预设。成功更新保留旧包。`kill -9`、断电及磁盘永久故障不属于自动恢复保证；残留安装锁需要先确认没有其他安装进程。

## 真实读取与资源记录

本机 Apple M2 Pro / macOS 27.2 (26B5091g)、arm64、Swift 6.4。系统枚举 Viper V4 Pro `1532:00E6 USB` 与 Reclusa Mini 65% `1532:02F5 USB`，共 9 个 HID 接口。输入接口仍观察到 Razer DriverKit 驱动；没有停止其他软件。

0.11.5 基线应用在 20:21:47 手动独立读取 Viper 电量为 78%；20:29:40 使用同版本 CLI 再读为 78%，两次相隔约 8 分钟。后一次模式为 `manual-status-queries; no setting commands`。这不是同一常驻调度器的自动刷新验收，也不证明无线外设持续在线或与 Synapse 长期共存稳定。

0.11.6 安装版在 20:36:17 原生界面单次读取为 77%，与上次查询相隔约 6 分 37 秒。整个过程只调用已有电量查询，未读取输入、修改 DPI 或回报率，也未试发 Reclusa 私有报文。

按需运行 `scripts/measure-native.py`，每秒从 libproc 取得累计 CPU 与 physical footprint；100% CPU 表示一个核心。基线为 0.11.5 / build 23，自动刷新和提醒关闭：

| 场景 | 时长 | 平均 CPU | footprint 中位数 / 最大值 | interrupt wakeups |
| --- | ---: | ---: | ---: | ---: |
| 主窗口打开，未查询 | 60 秒 | 0.0022% | 42.49 / 42.49 MiB | 20 |
| 一次电量读取及界面更新 | 60 秒 | 0.4802% | 47.80 / 60.80 MiB | 42 |
| 关闭主窗口后 | 180 秒 | 0.0280% | 54.64 / 54.67 MiB | 64 |

采样是普通开发桌面的有限区间，其他应用仍运行，没有锁定前台；单次查询区间含绘制及 UI 验证活动。三个区间不是完全相同负载，不用来宣称优化幅度、零 CPU 或无泄漏。子进程 CPU 增量均为 0，不代表不存在任何子进程。没有测量 GUI 首帧启动耗时。

安装版 0.11.6 另取两段 60 秒样本：

| 场景 | 平均 CPU | footprint 中位数 / 最大值 | interrupt wakeups |
| --- | ---: | ---: | ---: |
| 安装后主窗口打开 | 0.6595% | 44.69 / 53.05 MiB | 94 |
| 一次电量读取及界面更新 | 0.6518% | 56.11 / 69.13 MiB | 42 |

这两段的 CPU 和峰值高于前述部分基线区间，应保留而非忽略。窗口样本的 CPU 增量集中在第 40–50 秒区间，原因未归因；不能仅凭平均值判定持续后台活动或版本回归，也不宣称性能提升。两版窗口活动、启动后时间与采样时长并未严格配对；仍需可重复、同条件的后台和长时测量。两段子进程 CPU 增量为 0。

原始记录在 `build/performance0116/`、`build/ui0116/`、`build/phase0116-*.log/json`，仅保留本机，不上传原始设备数据。
