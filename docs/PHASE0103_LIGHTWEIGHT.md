## 资源测量方法

机器：Apple M2 Pro、16 GiB、macOS 27.2 (26B5091g)、arm64 / Swift 6.4。比较现有 0.10.2 / build 16 与本轮 0.10.3 / build 17 的 Release 应用，均无设备、跟随系统外观、自动刷新与提醒关闭。

`scripts/measure-native.py` 使用 macOS 自带 libproc 的 `proc_pid_rusage`，结构按本机 SDK `sys/resource.h` 的 `rusage_info_v1` 定义；不需要 pip 包。每秒记录累计 CPU、physical footprint、resident size、内核唤醒计数和已终止子进程累计 CPU，样本通过 UUID 与进程启动时刻检查身份。100% CPU 表示一个逻辑核心。

CPU 原始计数按 `mach_timebase_info` 转为秒，本机比例为 125/3。开发时的忙循环校验发现原始计数不能直接按纳秒处理，已修正；旧版样本的原始计数保留，并用同机 timebase 重算摘要。修正后已知忙循环测得约 98.35% CPU，已退出/无效 PID 均被拒绝。Apple 的[资源结构定义](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/sys/resource.h)和[子进程资源累积实现](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/kern_resource.c)可用于核对字段含义。

每段采样约 30 秒。主窗口打开后测一次，关闭主窗口后测一次；随后每版各启动一个新进程，实际打开/关闭设置一次和累计十次后分别采样，保留主窗口。新版另补累计二十次的检查。没有为了采样开启任何电量服务。

这些是日常开发桌面的短测：其他应用保持运行，部分区间同时操作独立模拟应用或编译，前台状态没有锁定。首次设置样本可能包括初次加载和绘制活动，不能把版本差异归因于某一改动。唤醒计数不等于全部计时器回调；子进程计数为 0 也不能证明期间从未启动子进程。

资源采样构建已包含本次所有布局变更；采样后仅将试验键盘的菜单动作名称改为“试读电量”，最终重新构建，未因该文案变化重复采样。环境记录保留采样时二进制的 SHA-256。

原始 JSON 和环境信息位于 `build/performance0103/`；构建目录不随源码上传，下面记录可供复核的摘要。

| 场景（每段约 30 秒） | 0.10.2 CPU % | 0.10.3 CPU % | 0.10.2 footprint 中位数 MiB | 0.10.3 footprint 中位数 MiB | interrupt wakeups 旧 / 新 |
| --- | ---: | ---: | ---: | ---: | --- |
| 主窗口打开 | 0.0056 | 0.0752 | 51.16 | 50.44 | 2 / 13 |
| 主窗口关闭 | 0.2371 | 0.1953 | 55.00 | 54.88 | 13 / 53 |
| 首次设置交互后 | 0.1415 | 0.0699 | 67.00 | 50.39 | 45 / 14 |
| 累计十次设置交互后 | 0.1022 | 0.1301 | 66.59 | 62.91 | 55 / 50 |

新版累计二十次交互后：CPU 0.1377%，footprint 中位数 49.00 MiB，interrupt wakeups 55 次。十次后的中位数高于首次，但二十次后回落，本组短测未表现为随开关次数单调增长；不能据此判定分配原因或排除长期泄漏。所有区间的子进程 CPU 增量为 0；package idle wakeups 除旧版十次设置区间为 2 外均为 0。

`vmmap -summary` 的后续独立快照显示 physical footprint 48.9M、peak 76.4M（工具原始单位），它与逐秒样本不是同一时刻；不能拿它替换较高的采样值。历史 0.9.2 的 RSS 增长与本轮 footprint 也不能直接相减。

没有定位到必须新增后台机制才能解决的问题；当前保持事件驱动和原有调度实现。本轮不宣称内存泄漏已排除，也不宣称 CPU/内存有确定性优化。长时运行、真实设备读数、睡眠唤醒和其他驱动共存仍需后续验收。

## 运行

```sh
./scripts/test.sh
./scripts/build-app.sh release
open build/RazerLite.app

# 对当前运行的正式版 PID 按需采样，输出保留原始数据。
python3 scripts/measure-native.py <PID> --seconds 60 --output build/idle.json

# 无硬件界面检查，所有设备服务被模拟。
./scripts/build-scenarios.sh
open -n build/RazerLite-Scenarios.app --args --scenario mouse
```

安装、登录启动、公证与真机验收的既有限制不变。下一步优先根据真实使用反馈修复问题；有设备后验证已有读取和 DPI 操作，不将宏、复杂灯效、应用关联加入近期范围。
