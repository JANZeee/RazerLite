# 原生前端改版

2026-10-17。基于现有 SwiftUI 应用修改，继续使用真实 DeviceManager；没有引入 WebView、网络资源或第三方 UI 库。

## 设计与交互

- macOS 原生窗口、工具栏、可调侧栏、菜单栏、设置窗口与保存面板；系统字体、SF Symbols、圆角和清楚的留白。
- 深色使用石墨灰分层，浅色使用暖灰与白色面板；雷蛇绿用于选中、品牌标记和关键图形。外观跟随系统。
- 设备总览突出名称、类型与示意图；USB 来自真实属性，电池/固件未读时显示“—”。“已发现”只表示主机发现 HID，不宣称接收器后的无线设备在线。
- 鼠标“性能”页保留 DPI / Hz 未读取状态，不编造当前值或支持范围。
- 键盘“灯光”页可选择 7 种本地预览颜色、拖动亮度，支持滑块键盘左右键与辅助功能调整。模型仅保存窗口内状态，无设备写入路径，无持久化承诺。该预览不代表硬件支持相应颜色或灯效。
- 按键页明确尚未开放；产品名称、VID/PID、版本属性、HID 接口、驱动绑定、协议来源、能力说明和诊断日志集中在设备信息中。
- 通用鼠标与键盘示意图使用 SwiftUI Shape / Canvas 绘制，不是精确产品照片或当前设备灯光。静态插画没有持续动画或帧定时器。
- 应用图标与侧栏采用一致的绿色 R 字标。`scripts/render-app-icon.swift` 用 AppKit 在构建时生成各尺寸 PNG，再由系统 iconutil 打包；只在图标源变更时重新生成，不增加应用常驻开销。
- 0.4.0 增加“档案”页：延续石墨灰、雷蛇绿和原生卡片层级，区分“本地选择”和“设备写入”。预设行显示 X/Y DPI、当前载入状态、导入/导出及删除入口；性能页以绿色小卡说明已载入的本地预设。菜单栏同样列出该型号可用预设。档案不是板载 profile，选择只填充输入框，设备写入仍需要原有检查和确认页。

## 验证

Debug 构建实际启动原生窗口，并从同一业务核心导出 2 款实物设备与虚拟 HID。使用 ImageRenderer 渲染实际共享的前端组件，产物位于 `build/design-preview/`：

- `keyboard-dark.png` / `keyboard-light.png`：键盘总览。
- `mouse-dark.png` / `mouse-light.png`：鼠标总览。
- `*-compact-*.png`：1000 pt 宽度下的布局。
- `performance-*.png` / `buttons-*.png`：尚未开放的控制状态。
- `lighting-*.png` / `lighting-purple-*.png`：本地预览 70% 绿色与 35% 紫色，渲染能正确反映状态变化。

已人工查看总览、窄窗口、性能、按键及灯光内容渲染，未见文字重叠或布局截断。渲染共用实际 UI 内容，但不包含系统窗口外框，侧栏滚动容器在渲染时展开；不能当成原生窗口交互自动化测试。实际鼠标点击、拖动、焦点、VoiceOver、设置和文件面板仍需在应用中人工体验。

0.4.0 的 Debug smoke 额外输出 `build/profile-ui-check/profiles-light.png` 和 `profiles-dark.png`。原生窗口还实际验证了：Viper 读取状态、创建本地 2800/2800 预设、载入性能编辑器，且没有触发 DPI 检查或写入。ImageRenderer 会把部分禁用的 AppKit 控件绘制成占位色块，因此它只用于布局回归；真实窗口的无障碍树和截图用于确认实际控件状态。

本次没有添加镜像布局实现的单元测试；沿用核心回归测试，并进行编译、实际启动与内容渲染检查。日志分别保存到 `build/design-tests.log` 和 `build/design-release-build.log`。设备控制边界保持只读发现，本地预览不会调用 HID report API。

最终 10 项核心回归测试通过，Debug / Release 构建通过，本地 ad hoc 签名校验通过，Release 应用已启动。图标资源已包含在签名的 bundle 中。

## 新版空闲资源样本

同一台 M2 Pro / 16 GiB / macOS 27.2，Release PID 50836，主窗口显示，现有 Razer 软件继续运行。预热后采样 15.198 秒、16 个样本，累计 CPU 时间无可测增量（计算为 0.0%，受 ps 精度限制）；RSS 为 105,520 KiB，约 103.0 MiB。随后 vmmap 报告 physical footprint 45.2M、peak 77.7M。采样不覆盖滑块拖动、首次渲染或长期后台状态，也不构成持续零 CPU 或内存改善的保证。

原始数据：`build/design-release-idle.csv`、`build/design-release-idle.json`、`build/design-release-vmmap.txt`。没有用这个样本推断 GUI 启动耗时。

## 0.2.0 真实状态查询

Viper V4 Pro 的指定查询接口已加入“读取状态”按钮。总览展示带时间的电量，性能页展示经过验证的 X/Y DPI、全部档位与当前档位；档位卡不是切换按钮。读取中禁止重复提交，部分成功或失败显示具体原因；旧值不冒充新结果。读取为手动触发，无定时更新，键盘灯光仍是本地预览。真机数据渲染位于 `build/read-ui-preview-final/`，查询记录见 [Phase 2 验证](READ_ONLY_PROTOCOL.md)。
# 0.8.1 界面精简 · 2026-10-19

本轮面向无外设时也可使用的原生界面，保留石墨灰、雷蛇绿与系统字体，浅色背景调整为中性灰白，卡片使用连续圆角。没有引入图片资源、WebView、动画定时器或依赖。

- 侧栏移除品牌下方重复说明，运行提示缩短为“自动发现设备”；目录入口有选中态，并避免同时选中设备与目录。
- 无设备页改为简洁的键鼠图标组合、单句引导与“浏览设备目录”按钮。存在设备但未选中时提示选择设备。
- 工具栏移除“本地模式”，保留刷新，将诊断导出收进“更多”。最低窗口尺寸为 960 × 640。
- 目录减少逐行重复的“型号参考”徽标，保留“型号收录不代表所有功能已适配”。增加搜索清除与无结果状态。
- 设备摘要说明改为状态徽标的悬停提示和辅助功能提示；成功读取不再占用整张提示卡，失败仍保留可见错误。读取/尝试时间、系统缓存来源继续显示。
- 总览移除长期为空的固件指标；固件未实现状态仍可在设备信息中查看。键盘查询细节改为展开说明，保留试验标识。
- 性能、灯光、按键和档案减少宣传及重复说明。灯光仍明确为本地预览，回报率仍区分配置与实测频率；DPI 仍提示整表提交和可能写入设备，独立确认页内容与写入流程未改。
- 设置页版本号读取 Bundle，修复显示旧 0.6.0 的问题；存储路径与诊断信息默认折叠。导出页保留完整目标、文件名和同名保护提示。

原生窗口验收覆盖当前深色外观下的无设备页、目录跳转、无结果搜索、`010D` 精确匹配、清除后恢复 273 项、设置页显示 0.8.1，以及“更多 → 导出诊断 → 取消”。本轮未保存诊断文件。设置页折叠项展开未完成交互验收；导出 sheet 的独立截图出现捕获异常，因此仅确认其入口、控件和取消操作，不将该截图视为视觉验收证据。

截图位于 `build/ui081/empty.jpg`、`catalog.jpg`、`no-results.jpg`、`settings.jpg`。没有外设连接，设备详情、DPI 确认和灯光页只通过代码审查及构建检查；浅色外观和更小窗口尚未逐项验收。未改变设备协议或后台策略，没有执行硬件查询或写入，没有新增性能指标。
