# 0.11.4：DPI 联动编辑与取消可靠性

日期：2026-11-06（Asia/Singapore），版本 0.11.4 / build 22。优先完善已可用的日常功能；不新增私有报文、依赖、轮询或后台服务。本轮真实设备只做被动枚举，所有设置验证均在隔离的假服务中完成。

## 用户可用的变化

- **X/Y 联动**：当前档位及每一行已有档位均可独立联动。开启时以 X 为准填入 Y，之后编辑任一轴同步另一轴；关闭只解除联动。提示明确这些操作只修改本地草稿。
- **载入当前值**：把已读取的当前档位填入编辑器，不额外查询设备。载入不对称设备值或档案时自动关闭联动；2846、6073 等非整步值完整保留，不取整。
- **输入反馈**：显示缺少轴值、非整数、范围或步进错误。多档未修改行不受新目标步进约束；只检查实际修改值。目标与已读取当前值相同时，不再提供无意义的检查操作。
- **操作冻结**：准备、待确认、应用和睡眠期间，输入、联动与载入操作共用忙碌状态。确认仍展示所有实际变化和完整档位表的提交范围。

不自动覆盖正在编辑的草稿，不增加档位数、不主动切档、不迁移档案格式。控制仍限已审查的 `1532:00E6 USB` 接口；联动不是新的设备协议。`ViperDPIInput` 为纯值模型，不保存许可或设备会话。

## 可靠性修复

### DPI 准备与应用的取消

原 DPI 准备取消只删除待确认计划：若准备请求还在执行，返回后可能重新展示确认。现在取消同时使准备会话失效；底层请求未返回时保留占用，拒绝重叠操作，迟到的计划被撤销，迟到错误不污染当前状态。

原 DPI 应用没有任务取消处理，串行队列中的工作不会自动继承 Swift Task 的取消。现在取消会立即撤销计划许可；尚未取得一次性许可的 SET 不能执行，迟到结果也不能恢复读数或成功标记。清理统一放在 defer，避免残留 busy/request 状态。已取消任务不能开始准备或提交。

已发送或已取得许可、即将交给系统的同步 I/O 存在不可撤回边界；取消不保证设备未变化，也不自动回滚。诊断继续保留“曾确认设备操作”的事实，不伪装成纯读取。

### 取消电量刷新后不显示旧值为当前值

组合读取取得电量后，独立电量刷新会清理统一电量结果。旧代码在取消后可能回退到仍保留在组合读数中的旧电量。现在菜单栏和总览摘要只有在电量能力的当前会话成功时才显示电量；旧值只留在带来源与时间的历史区。失败、取消、睡眠和等待不会把历史读数恢复为当前值；0% 仍是有效值。
