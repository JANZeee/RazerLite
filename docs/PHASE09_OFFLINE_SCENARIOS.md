# 0.9.0：离线场景与原生界面验收

日期：2026-10-19，Asia/Singapore。此阶段在无外设环境完成，不新增硬件协议或设备控制能力。

## 运行

```sh
./scripts/test.sh
./scripts/build-scenarios.sh
```

随后从 Finder 或 Codex 打开 `build/RazerLite-Scenarios.app`。它是独立 Debug 应用，bundle ID 为 `local.RazerLite.Scenarios`，可与正式的 `local.RazerLite` 并存。正式版本仍通过 `./scripts/build-app.sh release` 构建到 `build/RazerLite.app`。两个实际 bundle 均放在本机缓存目录，以避开 Documents 文件提供程序的签名问题。

也可在普通 Debug 可执行文件启动时传入 `--offline-scenarios`。Release 收到该参数或场景 bundle 标记时会在创建设备管理器前终止，不能回退到真实发现。

顶部开发栏可选择场景、局部外观，以及以下操作：

- “生命周期”：完成等待中的读取、断连、重连、睡眠、唤醒，以及 960×640 / 1180×800 内容尺寸。
- “DPI 结果”：模拟成功、未发送、读回不一致和计划过期。选择结果只决定假服务下一次的反馈；仍需在性能页准备并确认变更。
- 正式页面的读取、档案、确认与诊断导出入口继续可用，但操作全部进入假服务或独立临时档案库。

场景应用默认生成一个“模拟 · 办公”预设，目标为 1600/1600。示例鼠标当前第 3 档为 2800/3000，便于检验不同 X/Y 的呈现。这些数值均为人为构造，不是新取得的真机读数。

## 场景与状态

| 场景 | 检查内容 |
| --- | --- |
| 无设备 | 连接提示、目录入口 |
| 鼠标 · 完整读数 | 电量 76%、X/Y 不同、1000 Hz 配置、未充电 |
| 键盘 · 0% 电量 | 0% 有效、充电中、试验适配说明 |
| 蓝牙 · 系统缓存 | 系统来源与取得时间、0% 有效 |
| 未知型号 · 长名称 | 未启用私有后端、长标题、接口信息 |
| 两台同型号鼠标 | 独立会话、不同电量、互不覆盖 |
| 鼠标 · 尚未读取 | 只有接口信息，无默认电量或 DPI |
| 鼠标 · 等待响应 | 挂起假读取，显式释放后完成；没有定时轮询 |
| 鼠标 · 部分成功 | 保留电量，DPI 校验失败 |
| 鼠标 · 超时 | 无读数，不推断外设离线 |
| 鼠标 · 权限失败 | 权限类别及失败说明 |
| 仅接收器 · 状态未知 | 接口存在不证明无线端在线 |

重连会生成新的会话身份，不恢复旧读数或写入计划；需手动读取。等待中的旧响应可以在断连后释放，用于检查丢弃行为。

## 隔离实现

- `OfflineScenarioSession`、假发现与全部假服务由 `#if DEBUG` 包围，Release 不编译这些实现。
- 场景会话明确传入发现、鼠标、电池系统来源、回报率、充电、键盘电源和 DPI 控制的替代依赖；不使用管理器参数的真实服务默认值。
- 管理器在标为模拟时检查这些依赖，若混入任何现有真实服务则拒绝初始化。该检查防止误用现有默认依赖，不是任意第三方服务的沙箱。
- 场景服务只操作内存中的数据与 continuation；不访问 IORegistry、Feature Transport、system_profiler、网络或键鼠输入。
- 本地档案路径为系统临时目录下独立的 `RazerLite-Scenarios-<UUID>/profiles.json`。场景对象正常释放时清理自己的目录；强制终止可能留下临时文件。不会加载或覆盖用户正式档案。
- 窗口开发栏、菜单栏标题和 DPI 确认页都标注模拟；假读回结果也明确说明没有设备通信。
- 模拟导出继续采用 schema 6，新增可选 `dataOrigin`，同时使用 `mode: simulation-only; no device communication`。普通诊断没有此字段，旧 schema 6 仍能解码。模拟 attemptedWrite 等字段只表示假流程状态，不能用来证明 USB 写入发生。
- 旧 Debug smoke 路径在模拟会话中停用，避免其中直接创建真实 DPI 服务。

## 本轮界面修正

1. 顶部设备长名称按单行中部截断，提供完整名称悬停提示，并给状态标识保留宽度，避免挤掉刷新按钮。
2. 暂停后侧栏显示“发现已暂停”；窗口、菜单和设置中的刷新按钮在暂停期间禁用。
3. 模拟 DPI 确认页标注假服务，使用“确认模拟应用”；普通设备确认页保留原有具体变更与风险说明。
4. 实际使用正式窗口检查浅色/深色、滚动、五档 DPI、档案、能力说明展开和本地灯光颜色选择。

## 验证与证据

- `build/phase09-tests.log`：110 项测试 / 23 个 suite 通过。新增 8 项测试覆盖全部场景的来源标识、临时档案隔离、有效 0%、失败类别、未知型号拒绝、等待释放与去重、场景切换竞态、重连/睡眠失效、同型号会话隔离、模拟 DPI 单次确认/取消/过期/差异，以及旧诊断兼容。单项测试包含多个相关断言。
- `build/phase09-scenarios-build.log`：独立 Debug 场景包构建与严格签名检查。
- `build/phase09-release-build.log`：Release 构建与严格签名检查。
- `build/phase09-artifact-checks.json`：两个应用均为 0.9.0 / build 11、签名通过；Release 符号中未发现离线场景会话、工作台或假服务实现。
- `build/phase09-passive.json`：Release CLI 被动枚举为 0 台设备，mode 为 discovery-only；未请求 Feature 查询。
- `build/ui09/native-scenarios.json`：12 个场景在默认深色窗口中的可访问性状态检查。
- `build/ui09/light-compact-scenarios.json`：同样 12 个场景在浅色紧凑窗口中的状态检查。
- `build/ui09/`：由 Computer Use 获取的真实窗口截图与相应 AX 文本；包含长名称、鼠标性能、键盘、蓝牙、失败、档案和设备信息等。

原生 DPI 确认和模拟成功反馈已检查。等待读取可以手动完成；睡眠清除读数并暂停、唤醒保持未读、断连清空设备、重连保持未读已检查。SwiftUI 状态变化后的首次 AX 快照有时仍是上一帧，使用更新后的状态核对，不把单帧时序差异当作硬件结果。

最终版暂停后的“发现已暂停”和禁用刷新已另行检查，见 `build/ui09/sleep-final.txt`。原生导出页显示“导出模拟诊断”，默认文件名含 simulation；实际保存并解析 JSON 成功，mode / dataOrigin 的检查结果见 `build/phase09-native-export-check.json`。此次仅导出模拟数据到项目 build 目录。

组件 `ImageRenderer` 无法完整渲染本工具链中的部分原生控件，试验图出现占位图标，因此没有交付组件快照导出功能，也不以这些图片作为验收证据。尺寸变化时 Computer Use 曾返回缩小倾斜的捕获图；该图不作为布局结论，后续稳定窗口截图已能正常获取。

此轮覆盖默认深色、浅色紧凑及若干深色紧凑页面，并非每个页面、每个状态、两种外观与两种尺寸的全部交叉组合。X/Y 输入框点击与 Tab 操作已执行；不据此宣称完整 VoiceOver 或全部键盘导航已验收。未修改系统辅助功能设置，没有持续动画需要新增计时器。
