# 0.10.2：独立电量读取、低频调度与提醒

日期：2026-10-23。没有外设连接；本轮为软件、模拟协议与原生界面交付。

## 当前可用范围

- 设备页和菜单新增“读取电量”。Viper `00E6` 只发送既有、已审查的电量 GET，不附带 DPI、回报率或充电查询；键盘复用独立电量服务，蓝牙复用严格身份关联的系统电量服务。未知设备不尝试私有查询。
- 独立电量有自己的结果、来源和时间，不覆盖 DPI 或假更新它的时间。失败后不回退显示旧电量为当前值；上次成功值继续作为历史显示。既有综合读取会正确取代独立电量结果。
- 自动刷新和低电量提醒均默认关闭。只保存开关、5/10/15 分钟间隔及 10/15/20% 阈值，不保存电量历史或连接身份。
- **真实设备自动刷新未开放。** 三个生产后端尚缺重复读取和资源占用验收，界面禁用开启，并且 DeviceManager 再次校验资格。只有完全替换设备服务的离线应用能运行自动调度；型号收录、历史单次成功与模拟测试均不授予生产资格。
- 低电量提醒可由用户显式开启，通知服务查询实际系统权限。默认启动不请求权限；开启也不会追溯通知已有读数。真实系统授权和通知投递尚未实测，本轮只调用假通知服务。

## 调度与提醒行为

调度使用单调时间和一个可取消的单次等待任务。关闭、无合格设备、睡眠或全部设备忙碌时不创建刷新计时器；配置、插拔和读取完成通过现有事件触发重新安排。启用和唤醒后先等待完整间隔，不补发睡眠期间遗漏的查询。

已有手动操作时自动读取等待，新的手动电量结果推迟下次自动读取。自动电量进行中重复操作不会再发一次设备请求。全部自动读取一次只处理一台设备；系统蓝牙后端至少间隔 15 分钟，并共用全局启动预算，避免多台设备轮流启动快照进程。这个预算限制读取尝试，并非已测量的真实子进程频率，也没有引入共享原始蓝牙快照缓存。

超时、忙碌等按 2 倍间隔退避，最高 1 小时；权限、不支持、协议不匹配、无效数据等停止自动重试，待手动成功或新会话。关闭开关在计时到期及工作任务开始处再次检查，避免队列中已唤醒的任务越过关闭操作。

旧请求继续使用 0.10.1 的物理占用保护。Swift Task 取消不会强行中止同步 IOKit；底层实际返回前，不会放行同设备的新请求。

提醒仅处理事件流中新取得、有效的直接设备电量，允许 0%。未知、失败、未来时间、超过 2 分钟的读数、重复/乱序样本、历史值和系统缓存都不触发。系统缓存的应用取得时间无法证明设备采样时间，因此暂不用于提醒。

每个连接低于或等于阈值时只提醒一次；恢复至阈值以上 5% 后才重新允许提醒。投递失败不循环重试，等下一次新读数。设备断连、睡眠、关闭提醒和阈值改变会使尚未提交的旧提醒失效。已提交给 macOS 的通知仍受系统设置和投递时序影响，应用不保证系统一定显示横幅。提醒仅陈述电量，不推断充电或放电状态。

原生适配使用本地 `UNUserNotificationCenter`，只申请 alert，不注册推送、不申请声音或角标。依据：[Apple 通知授权](https://developer.apple.com/documentation/usernotifications/unusernotificationcenter/requestauthorization(options:completionhandler:))、[Apple 通知中心](https://developer.apple.com/documentation/usernotifications/unusernotificationcenter)。

## 验证

175 项测试、34 个 suite 通过。新增 21 项，覆盖：

- 只发送一个电量 GET，0% 有效，超时关闭接口，未支持 PID 不打开传输。
- 独立电量去重、硬件自动刷新资格阻断、断连迟到结果无事件，以及 DPI 值和原时间保留。
- 虚拟时钟下无立即查询、长请求不重叠、全局快照预算、退避上限、暂停和会话变化。
- 控制器实际等待任务在虚拟时钟下触发一次假电量读取，手动读取推迟时间，唤醒重排，关闭与到期竞争时不读取。
- 阈值跨越、恢复滞后、0%、重复/失效/缓存样本过滤、投递失败、权限拒绝/撤销、授权等待期间关闭与断连。
- 偏好默认关闭与读盘不改写，诊断、能力投影和界面共同使用独立电量结果。

日志：`build/phase0102-tests.log`、`build/phase0102-scenarios-build.log`、`build/phase0102-release-build.log`。

最终 Debug 离线构建和 Release 构建成功，两个 bundle 的 `codesign --verify --strict` 通过；版本为 0.10.2 / build 16。Release 依赖仅系统框架及 Swift 运行库，新增系统 UserNotifications 框架。

原生离线窗口实际点击“读取电量”取得假服务 15%，设置页实际开启/关闭调度和模拟通知，核对间隔、下次时间与权限来源。浅色/深色截图和辅助功能树在 `build/ui0102/native/`。没有等待真实 5 分钟来宣称调度实测，没有触发真实通知弹窗或硬件查询。

Release 也实际启动并打开设置，确认真实自动刷新开关禁用、提醒默认关闭、通知权限尚未检查。默认探针导出 schema 9，0 台设备，模式为 `discovery-only; no feature queries requested`，见 `build/phase0102-discovery.json`。这次枚举结果不能代表硬件兼容性测试。

诊断 schema 升为 9，新增可选 `batteryReadouts`，记录独立结果和来源；既有可选字段解码继续兼容旧导出。自动读取模式单独标记，模拟导出保留明确来源，模拟成功不提高硬件证据等级。

## 运行与待验收

```sh
./scripts/test.sh
./scripts/build-app.sh release
open build/RazerLite.app

./scripts/build-scenarios.sh
open -n build/RazerLite-Scenarios.app --args --scenario unread
```

离线应用：点击电量图标，进入设置开启自动刷新，可见 5 分钟后的计划。开启提醒只调用假权限服务，不改变系统通知权限。读取模拟 15% 可验证流程；自动时序以虚拟时钟回归为准。离线偏好域与正式版隔离。

真实应用：自动刷新暂不可开启，手动电量读取可用；提醒开启时才申请本地通知授权。蓝牙系统缓存暂不触发低电量提醒。

本轮未新增硬件兼容性、睡眠实测、真实通知交付或性能结论。Release 为本地 ad hoc 签名，不是公证分发包。自动刷新开放前需记录精确设备/固件、长请求、休眠重连、其他驱动共存，以及 CPU、physical footprint 和快照子进程成本；在此之前保持生产资格关闭。无外设时下一步可做性能采样与安装/错误体验，外设可用后进入既定 0.11.x 真机验证及设备控制。
