# 0.9.1：独立本地档案库

日期：2026-10-19，Asia/Singapore。当前没有外设用于验收。本阶段扩展本地配置能力，不增加设备协议或硬件兼容性结论。

## 使用

```sh
./scripts/test.sh
./scripts/build-app.sh release
```

打开 `build/RazerLite.app`，选择侧栏“本地档案”；菜单栏“打开本地档案”也能进入。关闭设备连接不影响本地预设的查看和整理。

可以新建预设、按名称/型号/DPI 搜索，从每行菜单编辑名称与 X/Y、复制、删除。顶部“导入…”先检查 JSON 并显示摘要，确认后才加入本地库；顶部更多菜单可导出全部预设。导出显示完整目标路径，拒绝覆盖同名文件。

本版仍只提供 Viper V4 Pro `1532:00E6` USB 的本地 DPI 目标。输入范围为 100–50,000，步进 50；名称最多 48 字符且不能包含换行。创建、编辑、复制、导入不会读取设备，也不会自动切换本地选择或应用参数。此前从真实读数保存预设的入口保留，行为仍是保存并选为本地预设。

## 载入与应用

没有匹配设备时，“载入编辑器…”禁用。有匹配连接时，目标页列出当前设备会话；只有一台时预选该连接，多台时需明确选择。会话 ID 用于区分当前接收器，不保存到档案。

载入会再次校验目标连接和预设内容，再进入对应设备的性能编辑器。它只填入 X/Y，不调用 DPI prepare / apply，不创建写入许可。设备实际读数、本地选择、编辑器目标和应用结果继续分别呈现；实际改动仍需“检查变更…”和确认页。断连或睡眠后的旧写入计划不恢复。

本地选择仍按型号目标保存，同型号接收器共享本地选择；此次对目标连接的选择只决定打开哪个设备编辑器，不代表已经建立永久的单件硬件绑定。

## 文件与容错

- 正式存储路径不变：`~/Library/Application Support/RazerLite/profiles.json`。
- 本地库和导出格式均保持 schema 1；不新增序列号、固件猜测、会话 ID 或写入许可。
- 编辑保留预设 ID 与创建时间；复制生成新 ID 和不超过名称上限的副本名称，不覆盖原件。
- 已打开的旧编辑或删除对象，如果 ID 对应内容已变更，会被拒绝，避免覆盖新的内容。
- 导入、加载、本地保存及导出均限制为 1 MiB；读取先按大小上限分块读取再解码，最多检查上限额外 1 字节。
- 同时保留最多 128 个预设限制。全部内容和容量通过校验后才提交，原子写入；后续一项无效时不会先保存前面的有效项。
- 导入预览不写文件、不改变本地选择。重复内容跳过，ID 相同而内容不同则生成新 ID 作为副本；确认时重新根据当前库计算合并。
- 写入前验证编码后的文件大小，避免极长组合字符造成字符数量虽少、文件却超限的情况。
- 损坏、超大或未来格式的现有库保留原文件并进入不可修改状态。界面显示“档案未载入”，不会把未知内容当作空库并覆盖。

## 原生文件面板的限制与替代

本机 SwiftUI `.fileImporter` 在选中有效 JSON 后仍显示不可打开；项目目录与 `/private/tmp` 的测试文件均出现同一情况，根因未确认。

当前导入采用应用内原生表单：可输入已有 JSON 的完整绝对路径，点击“检查文件”，阅读新增/重复/标识冲突摘要，再确认导入。路径变化会清除旧预览，不能误导入先前检查的数据。仍保留普通 `NSOpenPanel` 文件选择入口，由应用校验实际文件格式，不依赖系统 JSON 类型过滤。完整路径路线已验收；最终文件选择入口的选中确认仍需补充环境验证。

导出复用原有排他创建的 JSON writer，使用用户可见的目录和文件名；不依赖之前失效的 NSSavePanel 文件名流程。诊断导出与档案导出共用 `JSONExportSheet`，标题、说明、默认名称分别处理。模拟工作台中的默认导出名称和标题标注模拟。

## 验证

`build/phase091-tests.log`：118 项测试、24 个 suite 通过。新增 8 项测试覆盖：

- 无设备创建、编辑、复制、删除及重新实例化服务后加载，保持 schema 1。
- 副本名称上限与唯一副本名、过期编辑/删除/复制对象拒绝。
- 无效名称或 DPI、写入失败时内存与既有文件保持不变。
- 导入预览不写入、重复跳过、冲突副本与无操作导入不重写。
- 容量超限或后一项内容无效时不部分提交。
- 超大文件有界读取、现有超大库不可修改、目录输入拒绝。
- 极长单一组合字符无法产生下次启动不可读取的本地库。
- 模拟双设备场景中，档案操作及选择不调用任何设备读取或控制服务。
