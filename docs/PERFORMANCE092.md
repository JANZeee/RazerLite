# 0.9.2 空闲资源实测

日期：2026-10-22。本报告比较同机 0.9.1/build 12 与 0.9.2/build 13 的标准 Release 应用，不包含任何硬件查询或设置。

## 条件与方法

M2 Pro、16 GiB、macOS 27.2 (26B5091g)、arm64，CLT Swift 6.4。无 Razer 实物设备；Razer Elevation Service、GameManagerService 及原有系统扩展仍在运行。每个条件连续测 3 次，每次指定 60 秒，每秒读取主应用 PID 的累计 CPU 时间与 RSS。实际区间由 monotonic 时钟记录，均超过 60 秒；100% CPU 代表一个逻辑核心。

基线 PID 6398，新版 PID 7977。两版都使用系统外观、相同的无设备主窗口。条件依次为：

1. 主窗口保持打开、菜单关闭，启动活动结束后采样。没有持续锁定前台；其他应用交互可能使窗口进入后台或系统隐藏状态。因此文件名中的 `visible` 仅标识窗口打开，不能当作严格的全程前台可见实验。
2. 通过原生快捷键关闭主窗口，同一进程保留在后台。
3. 打开设置窗口，展开原生 **RazerLite 应用菜单**，Escape 收起，再关闭设置窗口，恢复后台空闲。

第三种实际测试的是应用菜单及设置交互后的恢复。当前自动化不能取得状态栏图标入口，因此没有把它标成 MenuBarExtra 状态菜单交互。真正状态栏菜单展开/收起及逐项点击仍待补测。

这是开发工作站上的初步同机比较：其他应用未关闭，采样期间进行了独立离线应用验收和部分编译；RSS 会受到系统回收、压缩及缓存影响。只统计目标主 PID，不把编译器、离线应用、Razer 服务或采样脚本计入应用 CPU。结果能描述本次空闲表现，不能单独证明变更的因果效果或排除低于噪声的回归。

脚本与复现方式：

```sh
python3 scripts/measure-series.py <PID> --label current-visible --directory build/performance092
```

每次 trial 保留 CSV 和 JSON，series summary 记录进程启动标识；跨 trial 检查 PID/启动命令未变化。采样分辨率有限，0.0000% 只表示该区间没有可分辨的 CPU 增量，不证明零工作。RSS 是 resident set，不能等同 physical footprint 或独占内存。

原始证据：`build/performance092/{baseline,current}-{visible,closed,after-app-menu}-{1,2,3}.{csv,json}`，对应 `*-summary.json`，以及 `environment.json`。以下按三次独立区间列出，不把单次瞬时值当性能保证。


## 结果

| 状态 | 0.9.1 CPU %（三次） | 0.9.2 CPU %（三次） | 0.9.1 RSS MiB（各次中位数） | 0.9.2 RSS MiB（各次中位数） |
| --- | --- | --- | --- | --- |
| 主窗口打开（前台未锁定） | 0.0000 / 0.2304 / 0.0822 | 0.0494 / 0.0000 / 0.0164 | 115.80 / 115.81 / 103.30 | 125.67 / 112.70 / 112.66 |
| 关闭主窗口 | 0.1315 / 0.0164 / 0.0658 | 0.0986 / 0.0000 / 0.0164 | 116.44 / 116.39 / 112.36 | 111.27 / 111.30 / 111.30 |
| 设置 / 应用菜单交互后 | 0.0165 / 0.1640 / 0.0987 | 0.0164 / 0.0000 / 0.0164 | 125.91 / 107.23 / 107.28 | 135.72 / 135.73 / 135.70 |

新版在这些区间的平均 CPU 最高约 0.099%，但没有据此宣称“零 CPU”或确定性优化。窗口显示和关闭的 RSS 与基线接近；设置/菜单交互后的新版 RSS 高于旧版，三次区间中位数的中位数约增加 28.4 MiB。该差异需要保留，不能只报告改进的状态。

针对这项差异进一步读取了新版进程的 `vmmap -summary`：physical footprint 为 **47.9M**，peak 为 **61.3M**（工具原始单位），malloc zone resident 合计约 31.2M。RSS 包含共享映射等归属差异，不能把 135.7 MiB 当作应用独占内存；也不能用新版 footprint 与旧版 RSS 作性能比较。本轮没有旧版 footprint，无法给出该指标的增减。

随后确认设置窗口的真实 AX 并使用关闭按钮重复开关 3 次：`ps` RSS 从一次后续检查的 133552 KiB 到 134608 KiB，physical footprint 从 47.9M 到 48.6M，peak 仍为 61.3M。三分钟空闲样本及这几次交互没有表现为不断大幅增长，但短测不能排除泄漏。设置控件、系统服务与渲染缓存的分配归因尚未完成；后续应在隔离环境用 Instruments 或同等分配工具对照，不把猜测写成原因。证据：`current-vmmap.txt`、`settings-repeat-vmmap.txt`、`settings-repeat-ps.txt` 和 `build/ui092/settings-repeat.txt`。

## 启动指标与未测范围

本次只读 CLI 的发现初始化约 **0.864 ms**，整个 CLI 生命周期 `real 0.04 s`，均是单次暖环境样本，原始输出在 `build/phase092-startup.log`。这两个数字不能替代 GUI 首帧启动时间；GUI 首帧仍未测量。

严格保持前台可见的窗口实验、真实 USB/蓝牙读取峰值、系统快照子进程、睡眠唤醒、设备插拔、真实状态栏菜单以及登录启动不在本报告的验证范围。公开发布前还需覆盖长时运行、多个设备、不同机器与系统版本。
