# RazerLite 下一阶段开发计划

## 2026-10-25 优先级调整：轻量、好用、易用

用户明确要求：轻量化工具，优先好用、易用，不必要的功能可以跳过。本节覆盖下文旧路线图中的未来优先级；已完成记录和硬件验证边界保留。参考雷云的常用操作，不以功能数量或完整复刻雷云作为目标。

**下一版建议为 0.10.3：精简日常体验与资源验收。** 当前仅更新计划，尚未实现或测量本节内容。

1. **精简主界面。** 设备页优先显示连接、电量与该设备已实现的常用操作；电量保留必要的历史/系统缓存标识。隐藏无实际设备控制的灯光预览入口，将接口、协议、适配证据和完整日志收进“设备信息 / 诊断”。未知功能用一句原因说明，避免整页灰色控制项；写入范围和确认仍须清楚。
2. **收敛菜单栏。** 优先设备、电量、读取状态、打开主窗口与退出。移除重复入口；没有外设时显示一个简洁空状态和连接检查入口。菜单展开不触发设备查询。
3. **减少设置负担。** 日常设置保留外观、登录启动、关闭窗口行为。电量相关选项按当前资格展示，无可用后端时用简短说明代替一组不可操作控件；开发和模拟信息留在离线应用/诊断中。保留现有配置数据，不为简化界面重写调度框架或新增依赖。
4. **测量并修复实际资源问题。** 用 Release 对无设备空闲、关闭主窗口后菜单栏常驻、重复打开关闭窗口/设置进行相同条件采样；记录 CPU、physical footprint、唤醒和相关子进程活动及工具限制。复查旧版设置交互后的内存增长，区分初始化缓存与持续增长，不预设结果，不用 RSS 替代 footprint。采样脚本按需运行，不把监测服务放进产品。
5. **验收。** 常用读取有清楚的忙碌、成功、失败反馈；浅深色可用；无设备无需阅读技术说明即可理解状态；默认无轮询，菜单打开不查询。现有核心回归测试与 Release 构建通过，记录界面检查与真实资源数据。真机和系统登录启动未验收的部分继续单独注明。

**之后只推进有直接收益的功能：** 有设备时优先复验已有读取和 DPI 设置，再完善常用 DPI 档位操作；自动电量在目标后端通过真实重复读取及资源验收后才开放。按实际使用设备逐个扩展适配，广泛被动发现仍保留，但不追求型号目录数量。

**近期跳过：** 宏、应用自动关联、复杂按键映射、逐帧/音乐 RGB、完整灯光编辑器、电量历史图表、续航预测、用户可执行适配包、云服务和自动更新。已有本地档案维持可用，暂不扩成复杂配置系统。只有出现明确日常需求且已有可靠协议依据时，才重新评估简单亮度/单色等功能。

新增功能的取舍顺序：是否解决经常遇到的问题 → 能否用更少操作完成 → 后台成本是否可控 → 是否有可验证的设备支持。满足不了时优先延后，不继续扩大框架。

## 1. 产品目标与真实起点

目标是成为日常可用的原生雷蛇管理工具：设备能被找到，状态可信，支持的参数能明确确认并可靠应用。界面参考雷云的设备、性能、灯光和配置组织方式，保留 macOS 原生控件与克制的信息密度。

| 能力 | 当前实际状态 | 下一步缺口 |
| --- | --- | --- |
| 设备发现 | 系统可见 Razer HID、USB/蓝牙、多接口聚合、热插拔；273 条型号参考目录 | 目录与可执行适配分离展示；非 HID 雷蛇设备、更多连接方式需要独立调查 |
| Viper V4 Pro `1532:00E6` USB | 电量、DPI、档位、配置回报率有历史真机读取；一次明确授权 DPI 修改与完整读回成功 | 充电查询、跨重连持久性待验证；完整档位编辑和回报率设置未交付 |
| BlackWidow `1532:02D2` USB | 电量/充电独立试验适配，模拟协议测试通过 | 真机读取、输入共存尚待验证；RGB 控制未实现 |
| 蓝牙 | `BSK MOBILE 068E:00D5` 曾发现并取得系统缓存电量 | 其他型号的系统属性覆盖；直接 BLE Battery Service 与私有协议须另做可行性验证 |
| 配置 | 离线创建、编辑、复制、搜索、导入/导出 Viper DPI 预设 | 完整档位表、可靠设备实例归属、应用关联；板载配置尚不支持 |
| 桌面体验 | 菜单栏、外观、关闭行为、页面与窗口恢复、登录项封装 | 状态栏真实点击、稳定安装后登录启动尚待验收；灯光页目前只是本地预览 |
| 工程质量 | 上轮 131 项测试 / 27 个 suite、Release 和本地签名通过 | 长时间运行、硬件生命周期、跨机与分发验证 |

当前没有硬件按键映射、系统重映射、宏、真实 RGB、固件查询或自动应用设备参数。设备版本属性不能冒充固件版本。详见 [README](../README.md)、[0.9.2 验证](PHASE092_PREFERENCES.md)。

### FerrisPulse 最新复查带来的具体决定

本次固定查看提交 `e0429c956ae82827cfce24bb33c85c4865070c33`（2026-10-21 UTC），重点为 [FDAS 规范](https://github.com/Ferris-echo/FerrisPulse/blob/e0429c956ae82827cfce24bb33c85c4865070c33/docs/ADAPTER_SPECIFICATION.md)、[运行时](https://github.com/Ferris-echo/FerrisPulse/blob/e0429c956ae82827cfce24bb33c85c4865070c33/src/Hardware/FdasRuntimeHelper.cs)及导入界面；不是完整安全审计。

规范提出指纹、能力和样本描述。运行时的 `QueryAllFdasDevices` 在实时读取失败时仍可能返回样本电量或默认 80%，鼠标 DPI 使用固定 1600；接口找不到精确匹配时还可能保留首个接口。因此不能直接把这条路径移植为真实设备读取。

RazerLite 采用描述与证据结构，但规定：样本只用于测试；未知值保持未知；接口不匹配就不打开；VID/PID 不是物理实例身份。规范中的写入模板也不等于运行时已完整实现或经过设备验证。首版只接受开发期审查、随应用编译的操作，不做用户导入 JSON 即获得设备发送权限的机制。

后续若移植实际代码，逐文件记录来源及许可证，另行处理发布义务。本轮只研究设计，没有复制上游实现。

## 4. 第一批：0.10.0 的具体任务

1. **建立适配证据清单。** 保存 adapter ID、VID/PID、transport、接口指纹、操作列表、固件限制（未知时明确未知）、来源提交、报文样本和验证记录。型号目录继续独立，273 条目录记录不变成 273 个可控制型号。
2. **拆开三个维度。** 功能实现：未实现/已实现；证据：公开实现参考/模拟通过/指定环境真机验证；当前会话：未读/读取中/成功/失败/断连。另有明确证据时才称“不支持”，没有实现不等于硬件不支持。
3. **改造能力展示。** 主页面只显示常用控制、最近状态和简短原因；证据、协议及接口细节收进展开项。未实现的键盘 RGB 不能显示成“实现完成、只待验证”。
4. **增加连接检查流程。** 按系统是否枚举、接口是否匹配、是否只有接收器、读取是否失败给出不同解释，提供现有诊断导出入口。默认只读系统信息，明确点击才进入已审查查询；不把申请所有权限作为统一解决方法。
5. **统一诊断输出。** 导出适配 ID、功能成熟度、当前结果、来源和时间。保留隐私边界，默认不加序列号、蓝牙地址或输入内容；增加字段时明确 schema 变化。

涉及 `AdapterCatalog`、`DeviceReadRegistry`、`DeviceReadSummary` 与相关 UI；先统一描述，不重写 Transport。验收覆盖未知 PID、纯系统蓝牙电量、试验键盘、已验证鼠标、两台同型号设备及部分失败。完成后交付一个可运行版本，再进入读取协调器。

## 5. 读取与电量：0.10.1–0.10.2

- 先迁移一种只读操作到小型协调器，验证后再迁移其余操作；DPI 写入的一次性许可保持独立。序列化真实 I/O；逻辑超时不意味着同步 IOKit 已被中断，不启动会重叠的新物理请求。
- 将连接会话、物理设备身份、型号身份分开。没有可靠持久身份时不自动绑定同型号设备，不拿 PID 当唯一设备 ID，不为解决这个问题默认采集序列号。
- 统一成功时间、应用取得时间、来源与有效性。系统缓存取得时间不能冒充设备采样时间；过期值可保留为“上次读取”，不能伪装为当前值。
- 一项明确不支持不必抹掉其他有效字段；断连、权限或传输失败按原因停止后续操作。零电量是有效值，未知充电状态不是“未充电”。
- 自动刷新默认关闭，由用户显式开启；候选频率先以分钟级实验确定，手动刷新优先且合并重复请求。睡眠、断连、连续失败时暂停或退避；`system_profiler` 使用单独的缓存与启动预算。
- 低电量提醒按阈值跨越和恢复状态去重，旧值/未知值不触发；仅开启提醒时申请通知权限。暂不做续航预测、电量历史图表或高频悬浮层。

验收包含虚拟时钟下调度上限、长调用、睡眠恢复、拔出重插、通知去重和 0% 电量。自动刷新只能先对完成真机验收的后端开放，其他后端保留手动试读与实验标识。

## 6. 真正的设备控制：0.11.x

### 先完成现有设备验证

复验 Viper 的现有读取与充电状态、BlackWidow 的电量/充电，覆盖无线外设关闭但接收器仍在、睡眠唤醒、重连、两台同型号、Synapse 同时运行。观察冲突并报告，不自动停止或卸载其他软件。

Viper 一次 2800/2800 写入读回成功后，后续记录再次读到 2846/2846，原因未确定。需要分步记录重新读取、重插、设备断电和其他软件运行状态，不能据此宣称板载持久性已经验证，也不能自动“纠正”设备值。

### 鼠标：完整 DPI 档位优先，回报率单独做

增加全部档位编辑、X/Y 联动与分离、当前档位选择、与设备值的差异显示。精确型号决定范围、步进和档位数；不能沿用其他鼠标的宣传参数。档位切换指令单独核对，不能因为已经能写档位数值就推定切换协议相同。

编辑仅改变本地草稿；应用前重新读取并检查当前会话/差异，展示提交范围，再明确确认。提交后读回整张表；不一致展示真实差异，不自动重试写入。已有单次授权不延伸到其他设置或未来操作。

本地档案扩展为带版本的档位数据，提供 schema 1 兼容迁移和失败恢复。菜单栏选择档案先载入/预览，设备写入继续确认。随后再独立实现回报率设置；支持哪些 Hz 由精确协议和真机证据决定，配置读回值不称为实测输入频率。

### 键盘：首个真实 RGB 闭环

以实际可获得、具有公开协议依据的设备为对象；`02D2` 是候选，不预先承诺其灯光可控。先亮度和单色，再考虑硬件呼吸/波浪。区分区域、临时设置与板载写入；能读取则读回，不能读取则记录 ACK 和人工可观察结果，不把 ACK 当作灯光已正确生效。

禁止在无源协议或无真机证据时把当前本地灯光预览改成“已应用”。首版不做软件逐帧 RGB、音乐联动或全键位动画编辑器。

## 7. 扩展设备、配置与按键

**设备覆盖：** 将“发现”“读取”“控制”列为三张明确的能力视图。先按可获得样本和协议完整性选每批 1–2 个适配，不按目录数量宣称支持。对未走 HID 的雷蛇音频等设备，先研究 IORegistry/USB 系统信息的被动发现与去重；蓝牙先完善系统属性，再验证目标设备是否发布可访问的标准 Battery Service。USB 报文不直接套到蓝牙，无可靠地址/服务身份关联就保持未适配。

**应用关联：** 可先通过系统应用切换通知选择或提示一个本地档案，不自动写硬件。自动应用设备参数是单独的后续功能，需要明确授权范围、回退和冲突规则；当前逐次确认规则继续有效。

**按键：** 优先研究精确型号的板载映射。软件方案先验证物理来源识别与事件拦截能力；CGEvent tap 本身不能作为按设备归属的保证。若只能全局映射，必须作为用户明确选择的全局模式，不能默认影响所有鼠标。需要处理权限撤销、tap 失效、组合键释放、断连和退出，失败时恢复正常输入。宏放在此基础稳定之后，禁止常驻记录用户输入。

## 8. 性能与发布门槛

- 当前 [性能记录](PERFORMANCE092.md)显示设置交互后的 RSS 对比上升约 28.4 MiB，但分配原因未归因；不能称为泄漏，也不能忽略。补同条件的旧/新版本 physical footprint、重复开关与长时运行，不混用 RSS 与 footprint 比较。
- 补真实状态栏菜单交互、严格前台条件和 GUI 首帧测量；现有应用菜单样本与 CLI 耗时不能替代。新增自动刷新需测设备调用和系统快照子进程的整体成本，记录硬件、场景、时长和原始结果。
- 安装脚本已具备但没有完成实际安装/登录重启验收。稳定安装、登录项启停、更新保留设置、卸载后登录项状态分别检查。
- 准备 Developer ID 签名、公证与安装包；证书/账号和真实发布动作届时明确处理。当前 ad hoc 签名不能当作正式分发验收。
- 发布兼容矩阵含型号、VID/PID、连接、接口、固件已知情况、操作和验证环境。部署目标 macOS 13、Intel 等没有真机证据的环境仍标待验证。

每批交付均包含可运行构建、适当的单元/模拟测试、操作说明和剩余限制。硬件功能另需匹配设备的真机记录；性能只报告实际测量。1.0 可以有明确范围，不必具备宏或所有型号支持。
