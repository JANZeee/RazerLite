# 0.12.0 — 键盘亮度

日期：2026-11-10；版本 0.12.0 / build 25，诊断 schema 11。

本轮为 Reclusa Mini 65% 的 `1532:02F5 USB` 接收器增加真实亮度读取、0–100% 目标编辑和关闭灯光快捷目标。基础功能保持按需执行，无动画刷新、自动恢复、定时器或新增依赖。颜色、呼吸、波浪及其他键盘不继承此次适配。

## 协议和实现

已独立核查官方产品映射、DualLink、灯区及亮度模块，来源、哈希和真机只读证据见 [键盘灯光协议](KEYBOARD_LIGHTING.md)。本机首次读取为灯区 5 / profile 1 / raw 255（100%）。静态开源项目的目录、相近型号或同为 90 字节报文都不作为兼容依据。

- Transport 仍只执行共享打开、Feature Report 收发和关闭，不接管输入。
- 协议层只实现灯区 GET、亮度 GET/SET，严格验证事务、响应、灯区与配置通道。
- 精确适配要求 VID/PID、名称、同一 USB 祖先、键盘 usage 及唯一 interface 3 指纹。
- 检查变更只读取基线；确认计划有效期 60 秒，每个许可最多一次写入。应用前重新比较灯区及原始亮度，再发一条 SET，并独立读回验证。
- 取消、睡眠、断连或关闭窗口使确认失效；底层返回前仍保留操作占用。写入后响应异常标为不确定，不重试或回滚。
- 亮度后端独立于电量 registry，不会因此开放键盘电量。诊断新增可选亮度读数和写入结果，历史导出仍可解码。

界面先显示“未读取”，有效读数后才显示编辑器。滑块及“关闭灯光”只改变草稿；真实写入需独立确认。移除旧的纯本地颜色/亮度预览代码，避免混淆。协议配置值不等于光学测量，实际灯光变化与跨重启保存单独验收。

## 运行与测试

```sh
./scripts/test.sh
./scripts/build-scenarios.sh
./scripts/build-app.sh release
python3 scripts/test-probe.py
./build/razerlite-probe --read-keyboard-brightness
```

命令行只有手动读取选项，无亮度写入开关。默认启动、枚举、热插拔、打开灯光页均不发送厂商命令。

247 项 Swift 测试、44 个 suite 通过，耗时 6.398 秒；Debug 场景版、Release 构建及 ad hoc 签名检查通过，CLI 帮助、默认被动发现和 8 条拒绝路径通过。覆盖协议错误、无依据的身份、多个灯区、busy 上限、基线变化、重复/过期/取消许可、异常 ACK、断连、迟到结果及诊断兼容。

Debug 模拟应用已原生验收：选择灯光场景，60% → 0% 仅编辑草稿，取消后读数仍为 60%，重新检查并确认后模拟读回 0%。模拟数据明确标识，所有服务已替换，不接触真实外设。

用户退出旧版后，标准 Release 已通过安装脚本更新至 `~/Applications/RazerLite.app`，旧包保留备份，安装签名验证通过。安装版真实界面完成手动 100% 读取及 100% → 50% 确认页检查。用户授权后恢复观察，界面已显示 50% 成功结果，因此没有重复执行写入；独立 CLI 读回 raw 127 / 50%。详见 [补充记录](KEYBOARD_LIGHTING.md#安装版-50-配置验收补充)。

用户随后确认：拖动滑块、检查变更并确认后，实际灯光亮度会变化。手动亮度调节的本机验收由配置读回补齐到可见效果；0% 关闭、断电保存、其他固件和连接方式仍待独立验证。本次仅补充验收记录，不重装应用或改变设备当前亮度。

构建日志、界面与硬件原始诊断只保留在忽略的 `build/`，不上传设备原始信息。
