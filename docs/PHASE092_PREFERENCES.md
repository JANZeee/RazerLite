# 0.9.2：设置、窗口行为与菜单栏

日期：2026-10-22。当前无外设，新增功能不扩大设备协议范围，不发送硬件设置或查询命令。

## 实现范围

- `AppPreferences` 使用原生 UserDefaults，仅保存外观、关闭主窗口行为和顶层普通页面。缺失或未知枚举值使用安全默认值，读取时不改写原值。默认跟随系统、保留菜单栏、设备页。
- AppDelegate 订阅外观变化，设置 `NSApp.appearance`，使主窗口、设置与原生应用菜单使用同一外观策略。系统状态栏菜单的实际呈现仍由 macOS 管理。
- 顶层页面可恢复为设备、本地档案或目录；不会恢复会话 ID、详情页请求、设备读数、选中接收器或写入许可。原生 NSWindow frame autosave 保存窗口位置和尺寸；模拟与普通窗口使用不同名称。
- 关闭主窗口立即使 DPI 待确认计划失效。选择退出时结束应用，终止流程停止发现服务并清理读数；默认保留菜单栏。设置、导出等窗口不触发主窗口退出策略。
- 菜单栏顶层优先显示设备名及已取得的电量；0% 有效。来源、各自取得时间及错误放在设备子菜单。系统电量标注缓存，展开菜单不触发查询。档案菜单对不同的 X/Y 同时显示两个目标值；选择仍只载入编辑器。增加设置入口。
- 版本更新为 0.9.2/build 13。诊断结构未变，仍为 schema 6；本地档案仍为 schema 1。README 改为当前能力与兼容性边界表，旧版说明移入 `FEATURE_HISTORY.md`，历史协议验收继续保留在对应记录。

模拟应用的设置单独存入 `local.RazerLite.Scenarios.Preferences`，可跨启动保留，设备档案仍使用每次会话的临时目录；正式应用使用自己的标准 defaults 域。

## 登录项与稳定安装

使用 macOS 13+ 的 `SMAppService.mainApp`，本机 SDK 的 `ServiceManagement.framework/Headers/SMAppService.h` 为实现依据。`LoginItemServicing` 隔离系统 API，`LoginItemController` 只在显式开关操作中调用 register/unregister。初始化、应用激活和设置打开仅重新读取状态，没有周期检查，也不根据本地布尔值自动注册。

界面区分未开启、已开启、等待系统批准、服务未找到和状态不可用。注册/注销异常保留实际系统状态并显示错误；需批准时提供系统登录项设置入口。用户拒绝后不会重试。

当前缓存目录中的构建不允许开启登录项。安装位置策略是本项目主动采取的产品约束：仅接受直接位于 `/Applications` 或 `~/Applications` 的 app，解析符号链接后重新检查；这不是“Apple 只支持这两个路径”的声明。模拟应用完全替换此服务，不接触正式登录注册。

准备安装与更新：

```sh
./scripts/build-app.sh release
./scripts/install-local.sh
# 退出已安装副本后更新：
./scripts/install-local.sh --replace
```

脚本只接受标准 Release 构建，先核对签名，暂存复制并再次检查，然后安装到 `~/Applications/RazerLite.app`。已有安装须显式 `--replace`，拒绝目标符号链接和非 RazerLite 包；旧包保留在 `Application Support/RazerLite/InstallBackups/previous.*/RazerLite.app`。不启动、不更改登录注册、不迁移或覆盖档案。若更新失败，可退出应用后将保留的旧包移回安装位置。更新后应重新核对系统登录项状态，不自动取消/重新注册用户设置。

**验收状态：** 已通过服务假实现与安装路径策略测试、脚本语法和签名检查。本轮没有执行真实安装脚本，没有注册登录项、注销或重新登录；ad hoc 签名的真实注册兼容性、更新后登录启动、Developer ID 与公证均待独立验收。

## 性能
