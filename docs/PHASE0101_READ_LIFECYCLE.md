# 0.10.1：读取任务与连接生命周期

日期：2026-10-23。开发与模拟验证版本；没有新增真机兼容性结论。

## 本轮交付

统一管理鼠标电量/DPI、回报率、充电状态、键盘电量/充电、蓝牙系统电量的请求生命周期。DPI 检查与应用也占用同一个设备操作槽，写入许可和确认流程继续由原有控制服务负责。

- 按具体设备会话隔离，不按型号或 PID 合并。控制接口指纹变化、断连重连、停止重启和睡眠都会使旧会话失效；普通属性刷新保留匹配的会话。
- 逻辑失效和底层结束分别处理。失效或取消的请求仍保留操作占用，直到服务实际返回。同一设备在此期间显示“等待上次操作结束”，读取和 DPI 操作均被阻止。
- 旧请求返回只释放自己的占用，不更新当前读数、历史值或待确认计划，也不能释放新请求的占用。不同物理设备独立管理；真实 Feature I/O 继续使用原有进程内串行队列。
- 支持调用方 Task 取消：丢弃本次结果，待底层结束后可手动重试。没有新增自动重试、定时轮询或操作超时后强制重开接口的逻辑。
- 每项保留本次连接的上次成功值、原始取得时间与来源。新读取期间及失败后，历史值单独展示；当前读数不会回填旧值。断连、指纹变化、睡眠和停止后清除历史，且不写入用户配置。
- 详情页摘要直接使用 DeviceManager 的共同状态，菜单和诊断沿用共同能力投影。详情页提供折叠的“上次成功读数”；菜单和功能说明也明确标注历史来源。
- 诊断 schema 升为 8，能力会话新增可选 `value` / `previous`，支持 waiting / cancelled 状态。schema 6 / 7 的历史诊断仍可解码。系统电量请求在执行期间也正确标记为系统元数据读取。

同步 IOKit 传输不能通过 Swift Task 取消立即终止。界面取消只使结果失效；如果底层长期没有返回，该设备的操作会继续被阻止。没有宣称新增硬性 I/O 超时或强制取消能力。

## 测试与构建

`./scripts/test.sh`：154 项测试，29 个 suite 通过。新增 10 项回归覆盖：

1. 旧会话失效后保留物理占用，旧清理不会释放新操作。
2. 普通属性刷新不改变会话；接口版本变化使其失效。
3. 同 ID 重连、睡眠唤醒、停止重启期间禁止再次读取，旧响应丢弃后可重新发起。
4. 调用方取消后的等待状态、占用保留、结果丢弃与取消原因。
5. 成功后刷新失败，历史值保留且时间不被刷新，JSON 与界面状态一致。
6. 一个字段失败不清空另一字段；枚举、能力摘要、连接检查和导出不额外查询。
7. 两台同型号设备独立响应，断开设备的迟到结果不能写入历史。
8. 已失效的 DPI 检查仍阻止读取，迟到计划无效且无法确认应用。
9. schema 7 缺少新增历史字段时仍可解码；既有 schema 6 回归继续通过。
10. 离线刷新失败场景的模拟来源、当前成功字段与历史失败字段分别显示。

## 无外设运行与调试

```sh
./scripts/test.sh
./scripts/build-app.sh release
open build/RazerLite.app

./scripts/build-scenarios.sh
open -n build/RazerLite-Scenarios.app --args --scenario retryFailed
```

独立离线应用现有 13 个场景，所有设备服务均为假服务；正式 Release 不包含场景实现。`retryFailed` 先生成成功读数，再让同一连接的充电刷新失败。可展开“上次成功读数”，同时检查当前失败和原先的时间、模拟来源。

在“鼠标 · 等待响应”场景中，从“生命周期”菜单依次选择模拟睡眠、模拟唤醒，可看到“等待上次操作结束”及禁用的读取按钮。选择“完成等待中的读取”后，旧结果被丢弃，按钮恢复，但不会自动再读。软件模拟睡眠不等于实际系统睡眠验收。

组件渲染和 JSON：`build/ui0101/`。真实原生窗口交互记录：`build/ui0101/native/`，包含历史值展开、唤醒等待和旧结果丢弃。浅色/深色组件截图与原生交互分开记录，不将组件渲染当成完整菜单和系统事件验收。

## 验证边界与下一步

本轮不发送真实设备查询或写入；只运行假服务、构建和默认被动探针。真实系统睡眠、硬件断连、不同固件、Synapse 共存及长时间 I/O 等待仍需实物验证。没有重测 CPU、RSS、physical footprint 或 GUI 首帧，不声称性能改善。

下一版为 0.10.2：默认关闭的低频电量刷新、休眠暂停与失败退避，以及可选低电量提醒。先完成调度与通知的离线验证，真实后端开启自动刷新前补对应设备及资源占用记录。完整 DPI 档位、回报率设置和 RGB 继续按 0.11.x 的真机与明确确认流程推进。
